# 甲方测试与上线说明

## 一、本地审阅

环境要求：Node.js 22.13 或更高版本，npm 10 或更高版本。

```bash
git clone https://github.com/HongbaiJoe/sunday-service-cn.git
cd sunday-service-cn
npm ci
npm run dev
```

浏览器打开 `http://localhost:3000`。本地数据库和媒体存储由 Cloudflare 开发运行环境模拟，不需要先购买服务器或手动安装数据库。

## 二、建议验收路径

1. 首页：检查首屏、翻档案滚动效果、各内容入口与移动端布局。
2. 登录和注册：在 `/login` 或 `/register` 输入测试邮箱或手机号。本地模式不会发送验证码。
3. 账户：在 `/account` 上传头像，修改名称、用户名、手机号和简介。
4. 社区（默认隐藏）：如需内部验收，在 `.env.local` 写入 `NEXT_PUBLIC_COMMUNITY_ENABLED=true` 并重启，再测试带图片、音频或视频的帖子、详情和回复；公开环境暂不设置该变量。
5. 资料库：提交资料，切换管理员身份，在 `/admin` 审核后确认内容公开。
6. 展厅：提交外部展览网址，审核后确认入口出现在展厅页。
7. 后台：检查帖子、评论、用户和审核记录管理，并测试 JSON 备份。
8. 双语：在每一页用左上角黑色语言按钮切换；预置内容应随界面切换，用户投稿保留原文，并在管理员录入译文后出现“查看英文翻译”。

## 三、自动检查

```bash
npm run lint
npm run typecheck
npm test
npm audit --omit=dev
```

`npm test` 包含生产构建及公开页面、账户、投稿、后台和数据绑定检查。任何正式发布分支都应先通过这些命令。

## 四、正式上线前必须完成

1. 接入真实邮箱验证码或短信验证码服务，完成账号找回、重复账号处理、会话过期和退出测试。当前邮箱/手机号入口只是本地原型。
2. 创建预发布环境，配置 Cloudflare D1、R2、正式域名和运行密钥，执行并验证 `drizzle/` 中的迁移。
3. 配置管理员白名单，使用真实成员和管理员账号完成权限与越权测试。
4. 增加登录、发帖、评论和上传的频率限制、反垃圾、举报与恶意文件检查。
5. 发布隐私政策、用户协议、版权投诉渠道，并确认艺人图片、专辑视觉、用户照片和宣传表述的授权。
6. 配置数据库自动备份、恢复演练、错误监控、运行日志和容量告警。
7. 在手机、桌面和主流浏览器完成上传失败、弱网、性能、键盘操作和减少动态效果验收。

完成以上事项后，先由甲方在预发布地址签字确认，再绑定正式域名开放公众访问。
