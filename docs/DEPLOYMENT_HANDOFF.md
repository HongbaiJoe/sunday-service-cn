# Sunday Service CN GitHub 与正式上线交付审计

## 当前结论

代码结构、依赖锁定、数据迁移、测试与文档已经具备整理为 GitHub 代码仓并交给甲方技术团队的条件。

但当前版本不应在没有部署准备的情况下直接开放给公众。最大的缺口不是页面代码，而是正式身份验证、内容安全、法律文本、运行监控和上线验收。

截至 2026-08-10，`npm audit --omit=dev` 对生产依赖的结果为 0 个漏洞。完整开发工具链仍有 6 个上游间接依赖告警，来自 Drizzle Kit 使用的旧版 esbuild 和 vinext 使用的 image-size；目前只有降级式修复建议，不适合在未做兼容验证时强行套用。交付后应在 CI 中持续审计，并在上游发布兼容修复后升级。

## 可以直接交仓的内容

- 完整页面、交互组件、响应式样式和中文内容。
- D1 数据结构、Drizzle 迁移和运行时初始化。
- R2 图片、视频和音频分片上传流程。
- 社区、评论、资料库、展览申请与管理员后台。
- 本地邮箱/手机号成员流程，以及头像、改名、手机号资料能力。
- 代码规范、类型检查、生产构建和页面自动测试。
- `.gitignore` 已排除依赖、构建缓存、本地数据库、临时文件和环境变量。

## 正式上线前必须完成

### 1. 邮箱与手机号身份验证

- 甲方选择并开通支持邮箱验证码、短信验证码和账号找回的身份验证服务。
- 配置正式域名、回调地址、密钥和短信签名。
- 完成邮箱/手机号验证、重复账号合并、退出、过期会话和账号找回测试。
- 当前手机号字段默认未验证，不能直接作为生产登录凭据。

### 2. 管理员与权限

- 确定首批管理员邮箱并写入部署环境白名单。
- 使用普通成员和管理员两个真实账号完成越权测试。
- 为停用、删除、申诉和数据导出制定操作规则。

### 3. 内容和媒体安全

- 增加发帖、评论、登录和上传的速率限制及反垃圾机制。
- 增加举报入口、审核规范和违规处理记录。
- 对公开上传文件增加恶意文件检查；需要时增加视频转码和缩略图任务。
- 明确单文件和账号总存储配额，评估 R2 与流量成本。

### 4. 法律与版权

- 发布用户协议、隐私政策、Cookie/身份验证说明和内容删除渠道。
- 明确用户上传作品、照片、视频和展览内容的授权条款。
- 逐一确认 Kanye West、其他艺人照片、专辑视觉和现有示例图片的正式使用许可；没有许可的素材必须替换。
- 确认“中国最大的黑人音乐社群”是否可以作为公开宣传表述。

### 5. 数据与运维

- 在预发布环境执行正式 D1 迁移并验证回滚或恢复流程。
- 设置定期自动备份；当前后台只提供手动 JSON 导出，不等于完整灾难恢复。
- 配置错误监控、运行日志、可用性告警和存储容量告警。
- 明确数据保存期限、账号注销和用户数据删除流程。

### 6. 上线验收

- 替换示例展览链接和所有占位内容。
- 在手机、平板、桌面以及主流浏览器完成交互、上传和权限回归。
- 完成键盘操作、对比度、替代文本和减少动态效果检查。
- 进行性能、并发、弱网和上传失败测试。
- 甲方在预发布地址签字确认后，再连接正式域名开放公众访问。

## GitHub 交付流程

1. 由甲方确认仓库归属、名称、公开或私有状态以及负责维护的账号。
2. 将当前目录提交为第一个可运行版本，附带 README、迁移和本审计文件。
3. 在 GitHub 启用分支保护、代码审查和敏感信息扫描。
4. 不把 `.env`、API 密钥、本地数据库、测试 Cookie 或用户上传文件提交进仓库。
5. 甲方技术团队从仓库创建预发布环境，完成上述正式上线前流程。
